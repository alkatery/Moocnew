# ADR-0004: التجارة وحدة معزولة خلف راية `payments.enabled`

- **الحالة:** مقبول
- **التاريخ:** 2026-06-09
- **السياق:** PRD §0.3، §1، §5.د

## القرار

كل ما يتعلق بالمال (الطلبات، الدفع، الفواتير، دفتر الأستاذ، السحوبات،
الاسترجاع) يعيش في سياق `Commerce` مستقل، محكوم براية واحدة
`payments.enabled` (Boolean). مُجمِّع الدفع المختار: **Moyasar** (mada /
Apple Pay / STC Pay)، يُفعَّل في مرحلة لاحقة.

## الأسباب

- المنصة تعمل بكامل وظائفها مجاناً، وتتحول للوضع التجاري بإعداد واحد دون
  إعادة بناء.
- فصل المال في سياق معزول يقلّل سطح المخاطرة القانونية/المالية ويبقيه
  معطّلاً افتراضياً.

## التبعات

- مصدر الحقيقة للراية: جدول `settings` (مُكاش في Redis)، يُقرأ عبر
  `FeatureFlags::paymentsEnabled()`. الافتراضي **false**.
- مسارات/واجهات `Commerce` **لا تُسجَّل** عند التعطيل.
- الالتحاق مفصول عن الدفع؛ `enrollments.order_id` اختياري (`nullable`)،
  والمفتاح الأجنبي لجدول `orders` يُضاف ضمن المرحلة 2.
- التحقق من توقيع webhooks الدفع و**idempotency** صارم منذ أول سطر في
  سياق `Commerce`.
